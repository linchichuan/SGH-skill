# SGH Assistant キャンセル・返金方針

> [!WARNING]
> **公開前レビュー用ドラフト（v0.1）／未施行**
> 正式提供時は、各requestの見積及び最終確認画面に、適用する具体的な取消・返金条件を表示します。

最終更新日：2026年7月20日

## 1. 基本原則

SGH Assistantの有料実行は、requestごとに状態を管理します。利用者は、実行開始前であれば、当社所定の方法で取消を行うことができます。

取消は、MCP、Web又はサポート窓口からの取消依頼が当社システムに受理され、当該requestが`CANCELLED`となった時点で成立します。AIが「取消を依頼しました」と表示しただけでは、取消完了とは限りません。

## 2. 「実行開始」の基準

正式提供時には、実行開始となるイベントを確認画面へ明示し、監査記録に保存します。原則として、次のいずれかが最初に行われた時点を実行開始とします。

- 通信事業者又は電話基盤へ、相手先に対する発信処理を送信した時点
- 人の担当者が、当該requestに固有の対外連絡、調査又は調整作業を開始した時点
- 利用者が個別に確認した見積に、これらと異なる開始基準が明示されている場合は、その時点

`DRAFT`、`NEEDS_USER_INFO`又は`AWAITING_CONFIRMATION`は実行開始ではありません。`QUEUED`も、外部発信又は人的作業がまだ開始されていない限り、実行開始ではありません。

## 3. 状態別の取扱い

| 状態・状況 | 取消と料金の取扱い |
|---|---|
| `DRAFT` / `NEEDS_USER_INFO` / `AWAITING_CONFIRMATION` | 無料で取消できます。電話・人的作業は開始されていません。 |
| `QUEUED`、かつ実行開始前 | 実行料金は発生しません。決済承認を解除し、確保済みの未使用クレジット又はPass枠を戻します。 |
| `CALLING`その他、電話試行開始後 | 取消後の新たな試行は停止します。開始済み試行の料金は、事前に確認された見積に具体的な料金がある場合に限り適用します。 |
| `WAITING_FOR_BUSINESS` / `CALLBACK_REQUIRED` | 既に行った試行又は人的作業は見積条件の対象となる場合があります。追加試行が見積範囲外の場合は、新たな確認を受けます。 |
| 人的作業開始後 | 開始済みの作業単位又は時間について、見積で明示した料金を適用します。未開始部分は請求しません。 |
| `CONFIRMED` / `COMPLETED` | 提供済み部分は原則として取消できません。不履行、誤課金又は重大な不具合がある場合は個別に調査します。 |

## 4. 未接続、話中、留守番電話及び相手先の拒否

未接続、話中、留守番電話、営業時間外、相手先の拒否その他予約等が成立しなかった場合でも、電話試行又は人的作業が実際に開始されていることがあります。

この場合に料金を適用するのは、申込み前の見積に次の事項を具体的に表示し、利用者が確認した場合に限ります。

- 1回の試行又は人的作業にかかる税込金額若しくは算定方法
- 料金が発生する開始イベント
- 見積に含まれる試行回数
- 再試行、折返し又は追加作業の条件

見積に記載のない未接続料金、再試行料金又は人的対応料金を、事後に追加しません。

## 5. 取消処理の競合

取消依頼と発信開始がほぼ同時に行われる場合があります。当社はrequest単位の原子的な状態確認により重複実行を防止しますが、取消完了前に実行開始イベントが記録された場合、開始済み部分には確認済みの見積条件が適用されます。

取消APIの再送は同じrequest及びidempotency keyについて一度だけ処理し、利用枠の二重返却又は重複返金を行いません。

## 6. 決済承認の解除

実行開始前に取消が成立した場合、当社は当該requestに関連付けた決済承認を解除します。決済承認の解除後も、カード発行会社又は決済事業者の処理により、利用可能額への反映まで時間を要する場合があります。この一時的な表示は、当社による売上確定と異なります。

## 7. SGH Pass及びクレジット

- 実行開始前：requestに確保した未使用のtask、電話又は人的対応枠をPassへ戻します。
- 実行開始後：実際に開始した部分は見積及びPass条件に従って消費し、未開始部分を戻します。
- 失効後又は有効期限経過後：返却先Passの利用可否は、Passの発行条件によります。
- sponsored Pass：利用者が現金を支払っていない場合、利用者への現金返金は行いません。発行元との精算は提携契約によります。

## 8. 返金

誤課金、重複課金、当社が実行を開始できなかった部分又は法令上返金が必要な場合は、調査のうえ、原則として元の支払方法へ返金します。返金の反映時期は決済事業者又は金融機関により異なります。

利用者が誤った電話番号、日時、氏名その他重要情報を提供したことにより再実行が必要となる場合、開始済み部分は確認済み見積の対象となり、再実行には新しい見積又は確認を求めることがあります。

## 9. 取消・返金の申出

可能な場合は、MCP又は管理画面の取消機能から対象requestを指定してください。利用できない場合は、次の情報をservice@shingihou.comへお送りください。

- request ID
- 取消又は返金を希望する理由
- 本人確認に必要な最小限の情報

カード番号、Pass Token、OAuth Token、病歴、パスポート画像その他の機微情報は送信しないでください。
